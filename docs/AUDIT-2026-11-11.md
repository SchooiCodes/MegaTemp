## 2. Findings — severity P0 (crash, data loss, security)

### B1. Windows `cp1252` crash: any redirected/piped output containing glyphs

*Where:* `utilities/etc.py` (`p_print`, `separator`, `status_line`,
`clear_console`), `utilities/menu.py:38-41`, `main.py` (`_storage_bar` and
`_action_storage`, `✓`/`✗`/`█`), `_test_smoke.py:76` (`→`).

*Symptom:* with stdout piped or redirected (CI, `| tee`, `> log`, GitHub
Actions on Windows, `subprocess.run(capture_output=True, text=True)`),
`print()` raises:

```
UnicodeEncodeError: 'charmap' codec can't encode character '\u2500'
```

Reproduced: `python _test_smoke.py` from a temp cwd dies at the first `→`.
`separator()` uses `─` (U+2500), `_storage_bar()` uses `█`/`░`, the menu uses
`╔ ║ ╚ ═`, health uses `✓ ✗` — none exist in cp1252. This makes `--health`,
`--extract`, `--loop`, TUI, and the smoke test crash on Windows whenever output
is captured. Tests pass only because `capsys`/`subprocess` use UTF-8 or no
encoding step.

*Fix (two layers):*

1. Central console shim, imported first in `main.py` (and in
   `_test_smoke.py`), e.g. new `utilities/console.py`:

```python
import os, sys


def init() -> bool:
	"""Make stdio total: never raise UnicodeEncodeError. Returns Unicode support."""
	for stream in (sys.stdout, sys.stderr):
		try:
			stream.reconfigure(encoding="utf-8", errors="replace")
		except (AttributeError, ValueError, OSError):
			pass
	return (sys.stdout.encoding or "").lower().replace("-", "") in ("utf8", "utf_8")
```

2. ASCII fallbacks when the encoding is not UTF-8 (`menu` glyphs and
   `_storage_bar`), plus `errors="replace"` remains the safety net.

*Regression test:* run `main.py --health --json` and `main.py --version` with
`PYTHONIOENCODING=cp1252` in a subprocess and assert return code 0.

### B2. Every MEGA API error becomes a `TypeError` (`mega_patch.py`)

*Where:* `utilities/mega_patch.py:54`

```python
raise RequestError(int_resp, response.status_code)
```

Installed `mega.py`:

```python
class RequestError(Exception):
	def __init__(self, message):
		code_desc, long_desc = _CODE_TO_DESCRIPTIONS[code]  # KeyError for unknown codes
```

*Symptom:* `TypeError: RequestError.__init__() takes 2 positional arguments but
3 were given` for **every** non-zero MEGA response (`-9`, `-4`, `-3`, `-15`,
…) and `KeyError` for codes outside the hard-coded map. Consequences:

* `services/alive.py` only catches `RequestError` → dead accounts produce
  tracebacks instead of a clean `FAIL`.
* retry logic (`utilities/retry.py`) cannot distinguish retryable from fatal
  errors.
* Real error messages (e.g. "account suspended") are never shown.

*Fix:*

```python
from mega.errors import RequestError, _CODE_TO_DESCRIPTIONS

if int_resp is not None:
	if int_resp == -3:
		raise RuntimeError("Request failed, retrying")
	code = int_resp if int_resp in _CODE_TO_DESCRIPTIONS else -1
	err = RequestError(code)
	err.http_status = response.status_code
	err.code = int_resp
	raise err
```

Also make `patch_mega()` idempotent (`if getattr(Mega._api_request, "_mt_patched", False): return`)
so a double import cannot double-wrap the method (each import in a test/reload
currently wraps again, doubling requests and breaking 402 retries).

*Regression test:* patch a fake response `[-9]` and assert `RequestError` with
`.code == -9`.

### B3. Upload crashes on files whose last chunk is ≤ 16 bytes

*Where:* `utilities/mega_patch.py:148-160`

```python
for i in range(0, len(chunk) - 16, 16):
	encryptor.encrypt(chunk[i : i + 16])
if file_size > 16:
	i += 16  # UnboundLocalError when the range was empty
```

*Symptom:* `UnboundLocalError: local variable 'i' referenced before
assignment` for any file > 16 bytes whose canonical last chunk is ≤ 16 bytes
(e.g. 131 077 bytes → chunks `(0, 131072)` and `(131072, 5)`; sizes
`131 073..131 088`, `393 217`, …). Registration can succeed and then fail at
the upload step; the account is still reported as created.

Also, files of exactly 131 072 + 16 bytes hit the same path.

*Fix:*

```python
last_start = ((len(chunk) - 1) // 16) * 16 if chunk else 0
encryptor = AES.new(k_str, AES.MODE_CBC, iv_str)
for i in range(0, last_start, 16):
	encryptor.encrypt(chunk[i : i + 16])
block = chunk[last_start:]
block += b"\0" * (-len(block) % 16)
encrypted_blocks[idx] = encryptor.encrypt(block)
```

*Regression test:* extend `tests/test_mega_patch.py` parity assertions to
sizes `{17, 32, 131073, 131077, 131088, 393217}` and compare
ciphertext/MAC with `mega.crypto.get_chunks` reference.

Minor cleanup in the same function: `with open(filename, "rb"):` is dead code;
`_fast_chunks`/`_FAST_CHUNK_SIZE` are documented as unused — remove or mark
private-only.

### B4. Hashcash timeout can hang forever

*Where:* `utilities/hashcash.py:66-76`

`as_completed(futures, timeout=...)` raises `TimeoutError`, the `with
ThreadPoolExecutor` block then calls `shutdown(wait=True)`, and the workers
loop `while not stop.is_set()` — `stop` is never set on the timeout path, so
`gencash()` never returns.

*Fix:*

```python
pool = ThreadPoolExecutor(max_workers=max_workers)
futures = [
	pool.submit(_search_worker, buf, threshold, w, max_workers, stop)
	for w in range(max_workers)
]
try:
	for f in as_completed(futures, timeout=timeout_seconds):
		result = f.result()
		if result is not None:
			return result
	raise TimeoutError("hashcash solving timed out")
finally:
	stop.set()
	pool.shutdown(wait=False, cancel_futures=True)
```

(Return inside `try` still runs `finally`, so solved challenges also stop the
pool immediately.)

*Regression test:* monkeypatch `_search_worker` to spin, call with
`timeout_seconds=0.05`, assert `TimeoutError` in < 1 s.

### B5. Encrypted credentials are unusable in export/extract/keepalive; `--prune` deletes them

*Where:*

* `services/extract.py:12-26` (`_load_all`) and `:127-150`
  (`extract_credentials`) read raw JSON.
* `services/alive.py:40` reads `data["password"]`, `:54` logs in with it,
  `:138-143` deletes the file when `--prune` is set.
* `utilities/fs.py:149-189` (`save_credentials`) writes `ENC:`/`OBS:`.

*Symptom:* with `--encryption-password` (or `config.encryptionPassword`):

* exports (`--export-bitwarden/-onepassword/-keepass`) put literal
  `ENC:gAAAA...` strings into the CSV;
* `--extract` writes `email#ENC:...` to `credentials.txt`;
* `--keepalive` always fails login, and `--keepalive --prune` **deletes every
  encrypted credential file** because "login failed".

*Fix:* add one helper in `utilities/fs.py`:

```python
def load_credential_file(path: str) -> tuple[dict, bool]:
	"""Return (decrypted data, was_encrypted)."""
	with open(path, encoding="utf-8") as fh:
		data = json.load(fh)
	enc = any(
		isinstance(v, str) and v.startswith(("ENC:", "OBS:")) for v in data.values()
	)
	if enc:
		decrypt_credential(data, _get_encryption_password())
	return data, enc
```

Use it in `extract._load_all`, `extract_credentials`, `alive._process_one`,
`main._load_entries` and `_action_storage`. Re-encrypt on write
(`encrypt_credential`) and **never prune** when the file was encrypted and
decryption failed (log "cannot decrypt, skipping prune").

### B6. `--keepalive --prune` has no confirmation and deletes on transient errors

`keepalive()` removes credential files after any `FAIL`, including rate limit
(`-4`), network outage, or a malformed file. Combine with B5 and one bad run
wipes the account database.

*Fix:* require `--yes` (or interactive confirmation) for `--prune`; only prune
on definitive auth codes (`-9` ENOENT, `-15` EBLOCKED, bad password), and keep
a timestamped backup (`credentials/pruned/`) instead of deleting outright.

### B7. `delete_default()` deletes the first root node — possibly a user file

*Where:* `utilities/etc.py:403-422`, called from `main.py:1019-1021`.

`pdf = mega.get_files_in_node(2); key = list(pdf.keys())[0]; mega.destroy(key)`
deletes an arbitrary file (dict order is server order, not name order). It also
runs via `asyncio.create_task(asyncio.to_thread(...))`, unawaited, so it races
the upload in the same function.

*Fix:* select by decrypted node name (`"MEGA"`/`welcome`/`.pdf` match), skip if
none; run it with `await asyncio.to_thread(...)` (or await the task) **before**
`upload_file` so the user's upload cannot be picked as "the default file".

### B8. Encryption is silently bypassed by CSV/JSONL/accounts.txt exports

*Where:* `utilities/fs.py:161-173` (accounts.txt), `:191-209`
(`save_credentials_csv`), `:230-241` (`save_credentials_jsonl`).

`save_credentials(..., encryption_password)` encrypts only the per-account JSON
path. `--export-csv` / `--export-jsonl` / `accountFormat` always write
plaintext, even when the user explicitly enabled encryption. The TUI's
"encryption password" setting therefore gives a false sense of security.

*Fix:* either document loudly that these formats are plaintext and require an
explicit `--allow-plaintext-export`, or apply the same `encrypt_credential`
transform. At minimum print a warning on every plaintext write when an
encryption password is configured.

## 3. Findings — severity P1 (features that don't work as documented)

### B9. `--mail-timeout` is parsed but never used

*Where:* `main.py` argparse defines `--mail-timeout` with
`default=120`, help "Seconds to wait…"; `register()` ignores it and calls
`get_mail(mail, max_attempts=config.mailTimeout)` (`main.py:918`), where
`Config.mailTimeout == 45` is an **attempt count** (2 s poll → ~90 s), not
seconds. Also README says 120.

*Fix:* treat `Config.mailTimeout` as seconds and convert once:
`attempts = max(1, round(seconds / POLL_INTERVAL))` with
`POLL_INTERVAL = 2` exposed in `utilities/web.py`; pass
`console_args.mail_timeout or config.mailTimeout` through `register()`,
`loop_registrations()`, `parallel_registrations()`; update README/default to
120 s.

### B10. mail.tm session cache is global — wrong mailbox in parallel mode

*Where:* `utilities/web.py:298-300` (`mail_login` returns
`_last_mail_account` regardless of `credentials.email`), `:437-438`, `:461`,
`:498`.

In `--loop N --parallel K`, worker B's `generate_mail()` overwrites the
singleton; worker A's `mail_login()` then returns B's mailbox, so A polls B's
inbox, never sees its confirmation mail, and burns all attempts. Single-worker
runs are unaffected.

*Fix:* cache per identity:

```python
_mail_accounts: dict[tuple[str, str], pymailtm.Account] = {}
key = (credentials.email, credentials.emailPassword)
mail = _mail_accounts.get(key)
...
_mail_accounts[key] = mail
```

Bound the dict (e.g. `collections.OrderedDict` + `popitem(last=False)`) so a
long loop does not leak. Also clear the entry when `generate_mail` creates a
new account for the same worker.

### B11. `mailtm` ABC provider calls APIs that don't exist

*Where:* `utilities/mailtm_provider.py:104` (`mail.login(...)`) and `:111-112`
(`mail.login(mailbox.address, "")`, `account.get_message()`).

`pymailtm` has no `MailTm.login`, and `Account` has only `get_messages(page)`,
`wait_for_message()`, `delete_account()`. Result: every registration routed
through the ABC with `--provider mailtm` fails immediately (the direct path in
`utilities/web.py` is used by default, so this only bites when the ABC is used —
e.g. via `utilities/provider.get_provider`). `Mailbox.address` is set to
`account.id_` and then treated as an address.

*Fix:* implement login/get_message against the real REST API (already done in
`web.generate_mail`): `Account(id, address, password)` then
`account.get_messages()`; store `address` + `password`/token in `Mailbox`
(add `token: str = ""` field in `utilities/provider.py`).

### B12. Guerrilla provider cannot complete a registration

*Where:* `utilities/guerrilla.py:39` (`password=""` → empty MEGA password),
`:67` (`sid = mailbox.address` — the e-mail address is used as `sid_token`).

`create_account()` puts the `sid_token` in `emailPassword` but `login()` drops
it, so `get_message()` always queries with the wrong token; and the generated
MEGA password is empty (the browser form then fails or creates an unusable
account). This matters because `main._PROVIDER_FALLBACKS` automatically falls
back to `guerrillamail`.

*Fix:* `Mailbox(provider=..., address=data["email_addr"], token=sid)`; read
`mailbox.token` in `get_message`; generate a real password with
`utilities.password_strength.generate_password()` (not `get_random_string`,
which is alphanumeric-only and rejected by MEGA's strength meter).

### B13. `--proxy-per-attempt` never rotates per attempt

*Where:* `main.py:606` and `:725` call `_build_browser_args()` once, before the
attempt loop; `register()` never rebuilds browser args. The proxy is fixed for
the whole browser lifetime, so the flag behaves exactly like "one proxy per
worker".

Config keys `proxy`, `proxyFile`, `proxyPerAttempt` are also dead: `setup()`
only builds `ProxyManager` from CLI args (`main.py:2139-2145`), so setting them
in `config.json` does nothing.

*Fix:* either (a) relaunch the browser with a new proxy between attempts when
`per_attempt` is set (expensive, ~1-3 s but correct), or (b) apply per-request
proxies to MEGA/mail calls via `requests` (browser fingerprint stays the same —
document the trade-off), or (c) rename the flag to `--proxy-per-worker` and fix
the docs. Merge config values in `merge_config` → `ProxyManager`.

### B14. Viewer search doesn't search what it says it does

*Where:* `main.py:1252-1265`. The prompt says "Search (email/notes/tags)", but
the filter only tests `e["key"]` (the JSON filename, i.e. the e-mail local
part). Searching a full address (`user@domain`) or any note/tag returns
nothing.

*Fix:*

```python
haystack = (
	" ".join(
		str((e["data"] or {}).get(k, "")) for k in ("email", "notes", "tags", "id")
	)
	+ " "
	+ e["key"]
)
```

Keep regex mode and apply the same haystack.

### B15. Viewer `a` deletes everything filtered, no confirmation, undocumented

*Where:* `main.py:1385-1400`; footer at `:1310-1313` lists
`p c C d n t / r Esc q` but not `a`.

Pressing `a` (easy to hit when reaching for `Esc`/`d`) silently deletes **all**
visible accounts, including `accounts.txt` entries, with no prompt and no undo.

*Fix:* require `prompt_yes_no(f"Delete all {len(filtered)} accounts? …")` and
type-the-count confirmation; add `[a] delete all` to the footer; or drop the
binding entirely.

### B16. Account actions use a hard-coded, unsanitized credential path

*Where:* `main.py:1880` (delete) and `:1907` (change password)
`f"credentials/{creds.email.split('@')[0]}.json"`.

Breaks when:

* the local part contains characters that `save_credentials` sanitizes
  (`+`, `%`, unicode → `_`),
* the account lives in `accounts.txt` (`accountFormat` set),
* a config profile is active (`set_config_profile`) — credentials path is not
  profile-aware at all,
* the file is encrypted: change-password then writes the new plaintext password
  into a file that still has `ENC:` in `emailPassword`, mangling it, and
  `delete_account` leaves orphan files behind.

*Fix:* add to `utilities/fs.py`:

```python
def find_credential_path(email: str) -> str | None:
	"""Locate the credential file/line for *email* (JSON, accounts.txt, profiles)."""
```

…and `update_credential(email, **fields)` that decrypts → mutates →
re-encrypts with the configured password. Use those from both actions.

### B17. `change_password()` likely sends the wrong protocol command

*Where:* `services/account.py:64`

```python
mega._api_request([{"a": "up", "pass": new_password}])
```

MEGA derives the login hash separately (`us0` salt → PBKDF2 → `uh`) and the SDK
has no "set password with plaintext" command (searched `commands.cpp` /
`megaclient.cpp`; `mega.py` exposes no `change_password`). The request will at
best return an error code (which B2 currently turns into a `TypeError`) and at
worst be a no-op that reports success.

*Fix:* remove the feature from the UI until verified against real MEGA traffic,
or implement the full handshake (fetch salt, derive `uh`/`k`, send the
password-key update) and test against a throwaway account. Also stop claiming
success without checking the response (see B2 — after the fix, a non-zero code
raises).

### B18. Unknown config keys crash startup

*Where:* `utilities/fs.py:103` and `:106` (`Config(**json_data)`).

A config written by a newer version (or hand-edited with a typo such as
`"attempts": 3`) raises
`TypeError: Config.__init__() got an unexpected keyword argument 'attempts'`
inside `read_config()` — before any error handling, so the TUI never starts.

*Fix:*

```python
known = {f.name for f in dataclasses.fields(Config)}
unknown = set(json_data) - known
if unknown:
	p_print(
		f"Ignoring unknown config key(s): {', '.join(sorted(unknown))}", Colours.WARNING
	)
	json_data = {k: v for k, v in json_data.items() if k in known}
```

Also stop writing to `config.json` from `read_config()` (line 104) — reads
should not mutate state (it also breaks read-only installs).

### B19. `--json` output is not guaranteed to be valid JSON

`_action_storage(json_output=True)` suppresses its own progress lines, but
`list_credentials()` → `decrypt_credential()` prints `Failed to decrypt field`
with `p_print` on stdout, and any `_validate_config` warning also goes to
stdout. So `main.py --health --json | jq` can fail.

*Fix:* add a global `set_json_mode(True)` in `utilities/etc.py` that routes
`p_print`/`separator` to `sys.stderr` (or drops below-WARNING messages).
Also `--health --json` still runs `setup()` (browser detection + possible
stdin prompt) first — see O1.

### B20. Health dashboard: unpatched, unbounded, no retry

*Where:* `main.py:1455-1556`.

* `Mega()` is constructed directly, not through `_safe_mega_session`, so it
  bypasses `patch_mega` only if `patch_mega()` had not run (it has, since
  `main.py` patches at import) — but it also **ignores hashcash/402**, has no
  timeout and no exponential backoff.
* `ThreadPoolExecutor(max_workers=min(20, max(5, n)))` fires up to 20 parallel
  logins → MEGA rate limit (`-4`), showing accounts as dead.
* `mega.login()` has no explicit timeout (requests default in mega.py).
* On dead accounts it prints only `✗` + colour (accessibility, see A2).

*Fix:* reuse `_safe_mega_session`, cap at `min(4, n)` by default with
`--workers`, add jitter, retry `-3/-4` once, and add `status` text
(`OK`/`DEAD`) alongside the glyph.

### B21. `auto_update()` can call `input()` from a daemon thread

*Where:* `utilities/etc.py:283-400`; started in `main.py:2149-2153` with
`_t.join(timeout=5)`.

For frozen builds this runs **before** CLI dispatch, can block 5 s on a slow
GitHub API, and calls `input("Update now? …")` from a background thread while
the TUI may be reading keys — two readers on stdin, garbled input and a hung
update prompt.

*Fix:* only check for updates after CLI dispatch (or via an explicit
`--update` / `check_update()` from the TUI), and only prompt when
`sys.stdin.isatty()`; otherwise print a one-line notice and exit.

### B22. `setup()` blocks non-interactive commands on a browser prompt

`--version`, `--health`, `--extract`, `--export-*`, `--list-cloud`,
`--keepalive` do not need a browser, yet `main.py:2155` runs `setup()` first.
On a machine without Chromium, `setup()` writes `config.json` and calls
`input(...)` (`main.py:540`) → hangs forever in Docker/CI/`cron`.

*Fix:* dispatch browser-free commands before `setup()`; in `setup()`, if no
browser is found and `not sys.stdin.isatty()`, print a clear error and
`sys.exit(2)` with a hint (`executablePath` / `--browser`).

### B23. `notify()` is intrusive on Windows

*Where:* `utilities/etc.py:21-55` — spawns a `MessageBoxW` thread on loop and
parallel completion. It steals focus, can appear behind the TUI, and is not
dismissable from the console.

*Fix:* use a toast (Windows `winrt`/`powershell -Command New-BurntToastNotification`)
or only notify when `--notify` is passed; never on Windows without consent.

### B24. Unverified account-cancel command

`services/account.py:46` sends `[{"a": "uc"}]`. MEGA's cancel-account flow
normally requires a confirmation hash (`uh`/`sid` + e-mail token) and may need
the account to be unlocked. Treat as unverified; test against a throwaway
account, and until then mark the menu item "experimental" and verify the
returned code (B2 makes failures visible).

### B25. `download_file()` timeout leaves a writing daemon thread

*Where:* `services/download.py` (`ThreadPoolExecutor`-based timeout). When the
timeout fires, the daemon thread keeps writing the file while the caller
returns `None`; on Windows this can produce a truncated file plus a later
`PermissionError` when the UI deletes/moves it.

*Fix:* use `mega.download(..., dest_path=...)` directly with a progress
callback and a proper cancel flag; or write to `.part` and rename on success.

### B26. Minor correctness/robustness

* `utilities/fs.py:427` calls `_get_encryption_password()` twice per listing.
* `utilities/fs.py:424,430,159,169` hard-code `"credentials"` instead of
  `CREDENTIALS_DIR`; `services/extract.py:22,127,131` and `:87` open files
  without `encoding="utf-8"` (Windows cp1252 → `UnicodeDecodeError` for
  non-Latin notes; CSV `newline=""` missing).
* `services/extract.py:87` writes the CSV with no encoding → crash on any
  character outside cp1252 (emoji in notes).
* `services/alive.py` imports `mega` at module import time (startup cost) and
  creates `Mega()` per account instead of reusing the session cache.
* `main.py:1321` `/` search does not reset `_regex_mode`; an invalid regex
  silently shows zero results instead of an error.
* `utilities/menu.py` may leave the cursor hidden if an exception escapes
  mid-render — wrap `run()` in `try/finally` restoring cursor + colours.
* `main.py:484` parses args at import time, so `import main` in tests/plugins
  can call `sys.exit` on bad args; move parsing into `main(argv=None)`.

## 5. Optimizations: startup, memory, runtime

### 5.1 Measured startup (this machine, cold process)

`python main.py --version` → **3.10 s**; `--health --json` (empty dir) → **3.08 s**.

`python -X importtime main.py --version` (cumulative self+cum):

| Module imported at `import main` | Cost |
| --- | --- |
| `pyppeteer` | **1.75 s** |
| `mega` + `utilities.mega_patch` | **1.59 s** |
| `requests` / `requests.adapters` | **1.31–1.42 s** (1.28 s inside `adapters`) |
| `trio` (pulled by `pyee` → `pyppeteer`) | 1.10 s |
| `utilities.web` | 0.67 s |
| `faker` | 0.56 s |
| `asyncio` | 0.29 s |

Cold single-module imports: `pymailtm` 1.46 s, `requests` 1.41 s,
`pyppeteer` 1.04 s, `faker` 0.81 s, `pyee`/`trio` 0.65 s, `urllib3` 0.30 s,
`mega` 0.11 s, `ssl` 0.15 s.

So **~2.5 s of the 3.1 s is imports that `--version`/`--health`/exports/
`--list-cloud`/`--keepalive` don't need**, and another ~0.5 s is `setup()`
(browser probing + config write) plus the update thread.

### O1. Lazy imports + early dispatch (biggest win: 3.1 s → ≈0.15–0.35 s)

1. Move argument parsing + dispatch into `main(argv=None)` (or `cli.py`).
2. Handle `--version`, `--health`, `--extract`, `--export-*`, `--list-cloud`,
   `--download-cloud`, `--keepalive`, `--help` **before** `setup()` and before
   importing `pyppeteer`, `utilities.web`, `services.*`.
3. Import at module level only `os, sys, argparse, json, time`.
4. Import inside the branches:
   * `pyppeteer` inside `_launch_browser`;
   * `utilities.mega_patch` + `services.*` inside the MEGA branches;
   * `utilities.web`/`pymailtm` inside `register()`;
   * `faker` inside `_get_faker()` (it already is lazily constructed, but the
     module import is top-level — move it);
   * `psutil` inside `kill_process()` (`utilities/etc.py:11` currently pays
     ~40 ms for every command);
   * `utilities.menu` inside `_run_tui()`.
5. Import `utilities.compat` only where tenacity is imported (or drop it once
   `tenacity>=9` is pinned — see O5).

Expected: `--version`/`--health`/`--extract` ≈ 0.15–0.3 s; TUI/registration
unchanged (they need the imports anyway), but no browser config/prompt for
non-browser commands.

### O2. Drop/relocate `pymailtm`

`pymailtm` is only used for: `MailTm._get_domains_list`,
`MailTm._make_account_request`, `Account(...)`, `Account.get_messages()`,
exception classes. `utilities/web.py::generate_mail` already talks to the REST
API directly. Replace the remaining calls with ~40 lines of `requests` and
remove the dependency (and its version-pin maintenance). It costs ≈1.4 s of
import (mostly `requests`) and is a stale, unmaintained wrapper.

### O3. Drop `Faker` (~0.8 s import, ~5 MB)

Only used to generate a plausible first/last name. Replace with two 50-entry
tuples + `random.choice` → removes a dependency entirely and ~0.8 s from
registration startup.

### O4. Replace `requests` with `urllib.request` in `utilities/web.py`

Three call sites (`/domains`, `/accounts`, message polling) would lose
connection pooling benefits, but a `urllib`-only module means the registration
path no longer imports `requests` at all (mega.py still does, but only when a
MEGA session is created). Net: ~1.3 s off startup and one less transitive
dependency for the mail flow. If you prefer keep-alive, use one module-level
`requests.Session()` instead (currently every call creates a new connection —
a real latency cost on `get_mail` polling).

### O5. Pin `tenacity>=9` in `requirements.txt`

`mega.py` declares `tenacity<6`, which is incompatible with Python ≥3.11
(`asyncio.coroutine`). The repo works around it with `utilities/compat.py` (a
global monkeypatch) and CI force-reinstalls. Pin `tenacity>=9` in
`requirements.txt`, delete the shim, and drop the CI workaround. Faster imports
and no global monkeypatch.

### O6. Pyppeteer is the single largest cost — pin or replace

* `pyppeteer` imports `pyee.trio` → `trio` (1.1 s) and `websockets`.
* It is unmaintained; Chromium download URLs are stale.
* Options, best → worst:
  1. **Playwright** (`playwright.sync_api`/async): maintained, bundled browser,
     faster startup, better selectors; +1 dependency but ~40 MB and no
     `trio`.
  2. Drive Chrome via `subprocess` + CDP over `websockets` directly for the
     handful of actions used (goto, type, click, waitForSelector) — removes
     ~5 dependencies.
  3. Keep `pyppeteer` but pin it and upgrade `pyee` if a release imports trio
     lazily.
* Also valid: registration via MEGA's API instead of the web form would remove
  the browser dependency for most flows (only e-mail confirmation is needed),
  at the cost of reverse-engineering/`appkey` stability — note as a research
  spike, not a quick win.

### O7. Runtime: MEGA sessions and parallelism

* `utilities/web.py` creates a new TCP connection per mail poll. Use a
  module-level `requests.Session` (thread-safe for GET/POST) → saves
  ~50–200 ms per poll and avoids TIME_WAIT buildup in parallel runs.
* `services/alive.py` and `main._action_storage` create a fresh `Mega()` per
  account; `services/upload.py` already has `_safe_mega_session` with caching
  (keyed by e-mail/password). Reuse it for keepalive/health → one login per
  account instead of two when both are used.
* Cap concurrency: default health/keepalive workers to `min(4, n)` and expose
  `--workers`; add ±20 % jitter to avoid synchronized bursts (MEGA `-4`).
* Parallel registration launches one Chromium per worker (~150–300 MB RSS
  each). Document `memory ≈ workers × 250 MB`; consider one browser + N
  incognito contexts (much lighter) if fingerprint correlation is acceptable.

### O8. Upload path

* `_upload_one` opens the file once per chunk; open once and `seek` in each
  worker (or `mmap` the file) → fewer syscalls, less page-cache churn.
* `max_workers=min(8, len(chunks))` is aggressive for small uplinks; make it
  configurable (`--upload-workers`, default 4).
* `session.close()` is in `finally` (good); ensure `raise_for_status()` errors
  include the chunk offset for diagnostics.
* Remove dead `_fast_chunks`/`_FAST_CHUNK_SIZE` (kept only for a test) or move
  them into the test file.

### O9. Hashcash solver

* The 12.5 MB buffer is required by MEGA's algorithm, but `_build_buffer` does
  `bytes(buf[...])` copies in a loop; build the 48-byte token block once and
  use slice-assignment from a pre-sized `bytes` (`buf[4:4+N] = token * k`) —
  ~10× faster buffer construction (once per challenge, minor).
* Use `max_workers=min(4, os.cpu_count() or 1)`; expose `--pow-timeout`.
* Cache solved challenges per token (MEGA may re-challenge the same session).

### O10. I/O and config

* `read_config()` writes `config.json` on every read when keys are missing
  (`fs.py:104`) — a syscall + possible permission error on read-only installs.
  Only write on explicit save.
* `list_credentials()` stats + parses every JSON on every TUI redraw inside
  `_action_view_credentials`? It is loaded once per screen open — fine — but
  `_action_storage` calls `list_credentials()` and then `Mega()` per account;
  cache the list for the duration of the command.
* `save_credentials_csv`/`jsonl` append per account (good), but write a header
  check via `os.stat` each time; cache `needs_header` for the process.

### O11. Packaging / distribution size

* `requirements.txt` includes `pyinstaller` (build-only) → move to
  `requirements-build.txt`; runtime installs are slimmer.
* `MegaTemp.spec` uses `collect_all('pyppeteer' | 'pymailtm' | 'mega')`
  (bundles tests, docs, metadata). Prefer `collect_submodules` + explicit
  datas, and `excludes=['tkinter', 'unittest', 'pydoc', 'email.test']`.
* Consider `--strip`/UPX already enabled; measure `dist/MegaTemp.exe` before/
  after.
* Ship a `uv.lock`/`pip-compile` output for reproducible, faster installs.

## 6. Accessibility

### A1. Encoding and colour

* B1 is the top accessibility issue: users on Windows terminals with legacy
  code pages, CI logs, screen readers piping output, and `NO_COLOR` users all
  hit it.
* Add `utilities/console.py` with:
  * UTF-8 reconfigure + `errors="replace"`;
  * `use_colour = sys.stdout.isatty() and not os.environ.get("NO_COLOR") and os.environ.get("TERM") != "dumb"`;
  * mutate `Colours` attributes to `""` when colour is off (single place, no
    call-site churn);
  * `ascii_only` flag (`--ascii`, `MEGATEMP_ASCII=1`) switching menu glyphs,
    `separator()` to `-`, and `_storage_bar()` to `#`/`-`.
* Respect `CLICOLOR=0`/`FORCE_COLOR` conventions.

### A2. Don't rely on colour or glyphs alone

* Health rows use `✓`/`✗` + colour only → replace with `OK`/`DEAD`.
* `p_print` colours messages but many strings have no status word
  (`separator`, progress). Prefix warnings with `[warn]`, errors with
  `[error]`.
* The upload/keepalive output uses `\r` in-place updates (`status_line`);
  screen readers and log capture see one garbled line. When `not isatty()`,
  print only on state changes or every N seconds with a newline.

### A3. Keyboard and non-interactive use

* Menu supports arrows/digits, but the footer doesn't document `j/k`, `q`,
  `Esc`, or `a`. Add a `?` help overlay listing all keys.
* Every hidden `input()`/`prompt_text()` must fail fast when
  `not sys.stdin.isatty()` (Docker, cron, CI). Currently `setup()` (B22) and
  `auto_update()` (B21) block.
* Add `--non-interactive` (or `--yes`) that turns all confirmations into
  errors unless explicitly acknowledged. Exit codes: `0` success, `1` runtime
  failure, `2` usage/config error.
* `--json` should be a stable machine interface: one JSON document on stdout,
  everything else on stderr (B19).

### A4. Readability

* `--quiet` currently suppresses info but not warnings; add `--verbose` levels
  (`-v`, `-vv`) and keep default output scannable.
* Colours: current palette is ANSI 256-less (`\033[9xm`), fine, but
  `Colours.ENDC` is appended to every line even when colour is disabled →
  strip both.
* Avoid all-caps shouting in messages; use `FAIL`/`WARN` tags.
* Long lines: `separator(width=60)` wraps poorly in 40-column terminals; read
  `shutil.get_terminal_size()` and clamp.
* `docs/` has no accessibility section; document `NO_COLOR`, `--ascii`,
  `--json`, and screen-reader-friendly `--plain`.

### A5. Locale / i18n readiness

* All file I/O must be `encoding="utf-8"` (B26) so non-Latin e-mails/notes
  round-trip.
* Timestamps: `datetime.fromtimestamp` is local (good); add `--utc` for logs.
* Number formatting is `f"{x:.1f}"` with `.` decimal — fine; avoid `,` in
  machine-readable `--json`.
* Password strength labels are English-only; fine for now.
